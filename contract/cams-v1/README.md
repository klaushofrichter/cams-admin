# cams-v1: the cams service API contract

The wire format between a cams instance and cams-admin (migration spec
`docs/superpowers/specs/2026-10-06-cams-admin-migration-design.md` §9.2).
Written source: cams-admin `contract/cams-build.ts` → `npm run contract:make`.
cams vendors this folder into its own `contract/cams-v1/` with a `SOURCE`
file naming the cams-admin commit, and tests against it.

| file | what |
|---|---|
| `*.schema.json` | JSON Schema (draft 2020-12), **lenient**: what a receiver accepts at run time (open objects, enums as plain strings) |
| `strict/*.schema.json` | the same, **strict**: closed objects, every listed field required, enums enforced. For tests |
| `fixtures/*.json` | `valid-*` (both accept), `invalid-*` (strict refuses), `drift-*` (lenient accepts, strict refuses) |
| `vectors.json` | fixed Ed25519 test keys (`server`, `cams`, `other`), the enroll proof, signed requests, signed answers and a signed snapshot: both repos reproduce every signature byte for byte |

Rules: a change goes into `contract/cams-build.ts` first (cams-admin PR),
`npm run contract:make`, commit; cams vendors it the same day. The check
order below is normative.

The cams service API (M §9.2) between a cams instance and cams-admin. Its written source is cams-admin `contract/cams-v1/` (lenient and strict JSON Schemas, fixtures, `vectors.json`, `README.md`), generated by `contract/cams-build.ts` through `npm run contract:make`. cams vendors it into `contract/cams-v1/` with a `SOURCE` file (the cams-admin commit) the way cam-proxy vendors `contract/v1/`. All paths are under `/cams/v1/`; every body is JSON (UTF-8); requests are at most 64 KiB, answers at most 1 MiB.

**Shared primitives** (byte-identical in both repos; cams copies cams-admin's `server/crypto/jcs.ts` verbatim as `server/admin/jcs.ts`):

- `jcs(value)`: RFC 8785, the P2 contract's function.
- `sha256hex(bytes)`: lower-case hex of SHA-256 over the exact body bytes (`""` for an empty body: `e3b0c442…b855`).
- Keys: Ed25519; public keys base64 SPKI DER (44 bytes), private keys base64 PKCS#8 DER; signatures base64 (88 characters) — as P1.

**Ids:** instance `^cms_[0-9A-HJKMNP-TV-Z]{20}$`; instance key `^key_…{20}$` (the P1 prefix, its own table); account `acc_`, proxy `prx_`, camera `cam_`, token `tok_` as P1/P2.

## Enrollment: `POST /cams/v1/enroll` (unsigned request, unsigned answer; as P1 §8.2)

Request (≤ 8 KiB): `{ "v": 1, "code": "CAC1-XXXX-XXXX-XXXX-XXXX-XXXX", "publicKey": "<b64 spki>", "proof": "<b64 sig>", "camsVersion": "<≤64>" }`.

- The code tag is **`CAC1`** (a proxy code is `CAE1`; neither endpoint accepts the other's), normalised like P1 (upper case, spaces/dashes dropped, `O`→`0`, `I`/`L`→`1`).
- `proof` = Ed25519 over `"cams-admin cams-enroll v1\n" + canonicalCode + "\n" + publicKey` (a different text from the proxy's `"cams-admin enroll v1\n…"`, so a proof can never be replayed across the two).

Answers: `201 { "v": 1, "instanceId": "cms_…", "instanceName": "cluster", "keyId": "key_…", "accounts": ["home"], "serverKeys": ["<b64 spki>", …], "serverKeyFingerprints": ["SHA256:…"], "apiUrl": "<origin the request came in on, if allow-listed, else PUBLIC_URL>" }`; `400 {error: "bad_request" | "bad_proof"}`; `401 {error: "invalid_code"}` (unknown, used, cancelled, expired or instance blocked: one answer); `429 {error: "rate_limited", retryAfterS}`. The new key is **pending** until its first verified signed request (as P1 migration 2's pending keys).

## Signed requests (every route but enroll)

Headers:

| header | value |
|---|---|
| `X-Cams-Instance` | `cms_…` |
| `X-Cams-Key` | `key_…` |
| `X-Cams-Ts` | integer ms (the instance's clock + its measured offset) |
| `X-Cams-Nonce` | 16 random bytes, base64url without padding (22 characters, `^[A-Za-z0-9_-]{22}$`) |
| `X-Cams-Sig` | base64 Ed25519 over the request text |

Request text: `"cams-admin/v1 request\n" + METHOD + "\n" + pathAndQuery + "\n" + ts + "\n" + nonce + "\n" + sha256hex(body)` where `METHOD` is upper case and `pathAndQuery` is the request target exactly as sent (origin-form, e.g. `/cams/v1/config`).

**Check order on cams-admin** (normative; the first failing step answers):

1. The five headers are present and well-formed, the body ≤ 64 KiB → else `400 bad_request`.
2. The failed-signature budget is not used up → else `429 rate_limited`: 300 per 10 min **per named instance** (an `X-Cams-Instance` of an existing instance), and one shared budget of 300 per 10 min for instance ids that don't exist. (Before step 1 a ceiling of 3000 requests a minute per well-formed instance id, and one for everything else, answers `429 rate_limited`, signed when the nonce is well-formed.)
3. The key exists, is not revoked, belongs to the named instance → else `401 unknown_key` (counts as a failed signature).
4. The signature verifies → else `401 bad_signature` (counts).
5. `|ts − serverNow| ≤ 300 000` → else `401 clock_skew` with `{"serverTime": <ms>}`.
6. The nonce was not seen in the last 10 min → else `401 replayed`.
7. The instance's state is `enrolled` → else `403 revoked`.
8. The instance's budget (60 requests per minute) allows it → else `429 rate_limited` with `retryAfterS`.
9. The route's own checks (JSON body, schema) → `400 invalid` with `field`, `404 not_found`, `409 …`.

A pending key that passes 1–7 becomes the instance's active key (any other active key is revoked, reason `re-enrolled`; audit `cams-key-confirmed`).

## Signed answers (every answer of a request that got past step 1)

`X-Cams-Admin-Sig` = base64 Ed25519 (cams-admin's signing key) over `"cams-admin/v1 response\n" + status + "\n" + requestNonce + "\n" + sha256hex(body)`. A `304` has an empty body. cams refuses an answer without a valid signature from one of its pinned `serverKeys` (`admin_answer_unsigned`), whatever its status; a `401 clock_skew` is the one unauthenticated-looking answer cams acts on, and only because it is signed too.

**Clock skew** (the Pi has no RTC): on a signed `401 clock_skew`, cams sets `offset = serverTime − localNow` (only when `|offset| ≤ 7 days`) and retries the request **once** with a fresh nonce. The offset is kept in memory and used for every later request until the next `clock_skew`.

## `GET /cams/v1/config` → the snapshot

`If-None-Match: "<revision>"` → `304` (signed, empty) when unchanged; else `200` with `ETag: "<revision>"` and the snapshot. The `ETag` header is not covered by the signature: cams compares the body's `revision` and its own stored value, never the header.

```json
{ "v": 1, "type": "cams-config",
  "instance": { "id": "cms_…", "name": "cluster", "rotateBefore": null },
  "revision": "r:0123456789abcdef", "generatedAt": 1791273600000,
  "accounts": [ {
    "id": "acc_…", "name": "home", "displayName": "Home", "revision": 17,
    "users": [ { "email": "user@example.org", "role": "admin", "disabled": false } ],
    "proxies": [ { "id": "prx_…", "name": "pi", "displayName": "Pi", "url": "http://127.0.0.1:8480",
                   "adminUiUrl": "http://192.0.2.20:8480", "tlsServername": null, "caFingerprints": [],
                   "tokens": [ { "id": "tok_…", "kind": "client", "state": "active", "retireAt": null } ],
                   "site": "garage" } ],
    "cameras": [ { "id": "cam_…", "camsId": "cam1", "name": "Backyard", "proxyId": "prx_…",
                   "proxyCameraId": "cam1", "host": "from-proxy", "protocol": "https",
                   "tlsServername": "cam1.example.net", "cameraUser": "cams",
                   "webUiUrl": null, "webUiNote": null, "moveId": null, "move": null } ] } ],
  "sig": "<b64>" }
```

- `sig` = Ed25519 (cams-admin's key) over `jcs(snapshot without sig)`, so the cached copy verifies at every start without a nonce.
- `revision` = `"r:" + first 16 hex of sha256hex(jcs({ i: <instance id>, iv: <instance version>, a: [[accountId, accountRevision], …] sorted by id, k: <signing key fingerprint> }))`. It changes when any served account's `config_revision` changes, when the instance's own row changes (served accounts, `rotateBefore`, routes), and when cams-admin's key changes. It is **not** ordered; cams compares it for equality only.
- `accounts`: exactly the accounts in `cams_instance_accounts` for this instance, sorted by `name`. ≤ 64 accounts; per account ≤ 500 users, ≤ 64 proxies, ≤ 256 cameras.
- `users`: every user row of the account (`email` lower case, `role` `admin` | `viewer`, `disabled`).
- `proxies`: **only** the proxies with a route row for this instance that is not hidden (routes are default-deny: a proxy nobody routed to an instance never reaches it, security review 2026-10-07; §9.6 + ruling R4-3); `url` = the route's URL if it has one, else the proxy's registered `url` (may be `null`); `caFingerprints` as registered (`SHA256:` + 64 upper-case hex, no colons, as P1's `normaliseFingerprint` stores them; cams normalises with its own `normalizeFingerprint`), except `[]` when `url` is plain http and not loopback (snapshot format 6, #106: cams takes pins only with https or loopback http, as `tlsServername` is `null` with any plain-http URL); `tokens` = the `proxy_tokens` rows **held by this instance** (`holder` = the instance id) in states `pending`, `active`, `retiring` (and `revoked` ones for 7 days after `revoked_at`, so cams can drop its copy) — ids, kinds, states and `retireAt` only.
- `cameras`: the account's cameras whose `proxyId` is null or a listed proxy; all P1 camera fields as registered (nulls kept).
- `proxies[].site` (camera moves): the TLS site name the registry holds, `null` or `^[a-z0-9][a-z0-9-]{0,30}$` (cam-proxy's `tls.site`); `cameras[].moveId`: the id (`mv_` + 20) of the move that currently holds the camera, else `null`. Both are required in strict and optional at run time (an older snapshot stays readable); cams derives nothing from TLS names.
- `cameras[].move` (move attestation, snapshot format 3): `{ id, sourceProxyId, targetProxyId, expiresAt }` or `null`. cams-admin emits it only while the camera sits on the move's target proxy and the move is in phase `switching`, `copying`, `cleaning` or `done` (a cancelled move puts the camera back, so none); `id` is the move's id (equal to `moveId`), `expiresAt` is ms since the epoch, 24 h after the switch-over. Required in strict, optional at run time. No second signature: the snapshot's signature covers it, and `instance.id` binds it to one cams instance. cams ignores it unless `id` equals `moveId`, `targetProxyId` is the camera's offered `proxyId`, and its own clock is before `expiresAt`. Then two rules (cams `TrustStore.decide`, both need a TLS name `<proxyCameraId>.<site>.internal` under the target proxy's `site`, a proxy URL, CA fingerprints, host and protocol): **A**, a confirmed camera moving from a trusted source proxy onto a not-yet-trusted target proxy trusts that proxy and confirms the camera; **B**, a camera new to this instance whose target proxy is already trusted with exactly the offered values (not held) is confirmed. Neither rule can introduce a proxy from nowhere for a new camera; both log `move-attested` with ids only.
- `accounts[].viewerTokens` (viewer tokens, snapshot format 4, design `docs/superpowers/specs/2026-11-05-viewer-tokens-design.md`): `[{ id: "vtk_…", name: "≤64", fingerprint: "sha256:<64 lower hex>", expiresAt: <ms> }]`, ≤ 64 per account, sorted by id: the tokens that include this account and are valid at `generatedAt` (not revoked, not expired). Required in strict, optional at run time (absent = none; today's cams ignores the field, and the signature covers it as received). `fingerprint` = `"sha256:" + hex(SHA-256(UTF-8("cams-viewer-token v1\n" + token)))`; a token is `cav_` + 22 base62 characters (≈ 131 random bits), so the fingerprint can't be reversed or guessed: it is the one hash a snapshot carries. The token itself never reaches a viewer except from the person signing in, and its sign-in link carries it in the fragment only: `https://<viewer>/token#t=<token>` (`vectors.json` `viewerTokens`: a fixed fake token, its fingerprint and link). A revoke, delete, shorter validity or account change bumps the accounts' `config_revision`; a natural expiry does not (cams compares `expiresAt` with its own clock plus its measured offset). cams signs in a person who presents a token whose fingerprint is listed, as a **viewer** of the accounts listing it, and checks the fleet again on every request.
- `accounts[].viewerTokens[].role` (snapshot format 5, spec 2026-11-08 A4): `viewer` | `admin`, the same in every account listing the token. Required in strict, optional at run time (absent = `viewer`: a snapshot from before format 5). cams signs a person in with an `admin` token as an **admin** of each account listing it (they can confirm held items and change that account's settings, like a Google admin of the account); a `viewer` token stays a viewer. Fixtures: `drift-snapshot-viewer-token-no-role` (run time reads viewer), `invalid-snapshot-viewer-token-role` (strict refuses `owner`); `valid-snapshot-two-accounts` holds one token of each role.
- **No secrets, ever:** no password, token, hash (but a viewer token's fingerprint, above), enrollment code or private key. A guard test fills every text column with a marker and checks the snapshot never contains a marker from `proxy_tokens.hash`, `enrollment_codes`, `cams_enrollment_codes` or a key.

## `POST /cams/v1/tokens`

Request `{ "v": 1, "proxyId": "prx_…", "kind": "client" | "admin", "hash": "sha256:<64 lower hex>" }`.

- The proxy must belong to an account the instance serves and have a visible route row for it → else `404 not_found`.
- Idempotent by hash: the same hash already held by this instance for this proxy and kind → `200` with that row.
- The hash held by anything else → `409 hash_in_use` (no detail).
- Another `pending` token of this instance for the same proxy and kind → `409 pending_exists` with `{"tokenId": "tok_…"}`.
- 3 live tokens of this kind held by this instance on this proxy (enough for one rotation), or 64 live tokens on the proxy → `409 too_many_tokens`; the P2 pre-checks (`409 unsupported_by_proxy`, `paused_on_proxy`, `not_allowed_on_proxy`, `proxy_ahead`) pass through unchanged.
- Else `201 { "tokenId": "tok_…", "state": "pending", "label": "cams <instance name>" }` (a `kind: admin` label is `"cams <instance name> admin"`), and a `tokens.apply` is queued with actor = the instance id.

## `POST /cams/v1/tokens/:tokenId/retire`

Request `{ "v": 1, "hours": 24 }` (`hours` optional, integer 1–168, default 24). Only a token held by this instance (else `404 not_found`) in state `active` (else `409 not_active`). Answer `200 { "tokenId": "tok_…", "state": "retiring", "retireAt": <ms> }`.

## `POST /cams/v1/report`

Request (≤ 64 KiB):

```json
{ "v": 1, "mode": "cams-admin", "version": "2026.10.07.1",
  "appliedRevision": "r:0123456789abcdef", "cacheVerifiedAt": 1791273600000, "lastPullAt": 1791273600000,
  "held":    [ { "accountId": "acc_…", "camsId": "cam1", "fields": ["host"] } ],
  "keptOld": [ { "accountId": "acc_…", "camsId": "cam1", "fields": ["host"] } ],
  "heldProxies": [ { "accountId": "acc_…", "proxyId": "prx_…", "fields": ["proxyUrl", "caFingerprints"] } ],
  "shadow":  { "accountId": "acc_…", "differences": 0, "items": [] },
  "tokens":  { "managed": 2, "pending": 0, "legacy": 0 },
  "problems": [ { "code": "snapshot_invalid", "accountId": "acc_…", "detail": "camera 3: protocol" } ] }
```

`mode` `file` | `shadow` | `cams-admin`; `appliedRevision`, `cacheVerifiedAt`, `lastPullAt` may be null; `held`/`keptOld` ≤ 200 entries, `fields` ⊆ the trust fields `proxyUrl`, `caFingerprints`, `proxyTlsServername`, `host`, `protocol`, `tlsServername`; `shadow` null outside shadow mode, `items` ≤ 20 strings of ≤ 200 characters naming a camsId and a field, never a value; `problems` ≤ 50, `code` ≤ 64, `detail` ≤ 200. `viewerTokens` (optional, ≤ 200): `[{ id: "vtk_…", lastUsedAt: <ms> }]`, the newest use of each viewer token since the last report; cams-admin keeps it (never in the stored report) for tokens of accounts the instance serves, in memory and in its 10-minute status snapshot. Answer `200 { "changed": <revision ≠ appliedRevision>, "revision": "r:…" }`. cams sends one at start, then at most one per 60 s, and at once after a held change is confirmed or kept. `heldProxies` (camera moves) is optional, ≤ 64 entries, each exactly `{accountId, proxyId, fields}` with `fields` ⊆ `proxyUrl`, `caFingerprints`, `proxyTlsServername` (no values).

## `GET /cams/v1/accounts/:accountId/fleet`

One account's fleet for the cams MCP's admin tools (design: cams `docs/superpowers/specs/2026-11-04-mcp-fleet-tools-design.md`). Read only; nothing is written and cams keeps it at most a few seconds. After the check order: the account must be in `cams_instance_accounts` for this instance, else `403 not_served` (the same for an account that doesn't exist). Answer `200`, schema `fleet-response`:

```json
{ "v": 1, "type": "cams-fleet", "accountId": "acc_…", "generatedAt": 1791273600000, "notRouted": 0,
  "proxies": [ { "name": "pi", "displayName": "Pi", "state": "online", "version": "2026.10.07.1", "ok": false, "problemCount": 1, "reportedAt": 1791273600000,
                 "gui": { "url": "http://192.0.2.20:8480/", "scope": "public", "note": null },
                 "problems": [ { "id": "disk", "label": "Disk", "text": "91% full", "camera": null } ],
                 "cameras": [ { "id": "cam1", "name": "Backyard", "online": true } ] } ],
  "viewers": [ { "name": "cluster", "displayName": "Cluster", "thisViewer": true, "address": null,
                 "held": [ { "camera": "cam1", "fields": ["host"] } ], "keptOld": [], "heldProxies": [ { "proxy": "Pi", "fields": ["proxyUrl"] } ], "heldTotal": 2 } ],
  "moves": [ { "id": "mv_…", "camera": "cam2", "cameraName": "Driveway", "source": "Pi", "target": "Cluster", "phase": "copying", "reason": null,
               "bytesTotal": 1000, "bytesDone": 400, "rateBps": 100, "etaS": 6, "chunks": { "pending": 1, "copied": 0, "verified": 2, "skipped": 0, "failed": 0, "abandoned": 0 },
               "createdAt": 1791273540000, "updatedAt": 1791273600000, "endedAt": null } ] }
```

- `proxies`: the account's proxies routed to this instance and not hidden (the snapshot's default-deny rule); `notRouted` counts the account's others. `gui` is `adminUiUrl`, else `url`, with `scope` and `note` from `contract/address.ts` (`null` without an http(s) address). `problems` ≤ 20 per proxy, the problem items of its last summary, in the proxy's own words; `camera` is the camsId, `null` for the proxy as a whole or a camera this account doesn't have.
- `viewers`: the enrolled instances serving this account (≤ 32). `held`, `keptOld`, `heldProxies` (≤ 50 each) hold only that instance's report entries for **this** account, by camsId and the proxy's display name; `heldTotal` is the number before the cap. **Never** another account's id, name or count, an instance's account list, or a value.
- `moves`: this account's newest 50. `source` and `target` are proxy display names, `null` for a proxy outside the account; `reason` is a code, the free-text detail is left out.
- `switches` (PoE switches, design `docs/superpowers/specs/2026-11-07-poe-switches-design.md`; the cams MCP's `switch_list`): `[{ name, model: "sscpoe-web", address: {url, scope, note}|null (http://<switch address>/, as `gui`), proxy: <operating proxy's display name>|null, state: "pending"|"active", readAt, ports, problems: [{ code: "chained_switch", port, cameras }] }]`, ≤ 64. `problems` come from the switch's latest survey: `chained_switch` = two or more cameras behind one port (another switch chained on it; a configuration issue). Never a switch id, serial, firmware or password.
- `cameraPower` (the cams MCP's `camera_power`): `[{ camera: camsId, cameraName, kind: "poe"|"data-only"|"adapter"|"unknown", switch: <switch name>|null, port|null, watts|null, verifiedAt|null, notSeen, lastCycle: { state: "running"|"ok"|"failed", requestedAt, finishedAt, code, reason }|null }]`, ≤ 256: the cameras on a proxy routed to this instance or on none, by camsId. Never a command id.
- `switches` and `cameraPower` are required in strict and optional at run time (an older cams-admin leaves them out). cams vendors this folder: re-vendor after a change here.
- **No secrets, ever:** no token, hash, key, CA fingerprint or camera password, and no audit rows. Fields are named one by one (`server/cams/fleet.ts`); a guard test fills the rows with markers and scans the answer.
